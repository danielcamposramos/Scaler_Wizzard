# Research Design: Tiny Recursive MoE Contrastive (TRMC) Model

**Date**: 2025-11-17
**Author**: Jules (AI Partner)
**Concept**: Fusing recursive reasoning, parameter-efficient MoE, and contrastive learning for robust small-scale AI.

## 1. Architectural Foundation: Tiny Recursive Model (TRM)

Inspired by the "Less is More: Recursive Reasoning with Tiny Networks" (2025) paper, the TRMC model uses a small transformer core recursively.

- **Recursive State**: The model maintains a latent state $z_t$ and a prediction $y_t$.
- **Update Rule**: $(z_{t+1}, y_{t+1}) = \text{TransformerCore}(x, y_t, z_t)$.
- **Parameters**: Targeted at ~7M to 20M parameters.
- **Recursion Depth**: 8 to 16 steps.

## 2. Capacity Enhancement: Mixture of Experts (MoE)

To increase the model's "knowledge capacity" without proportional increases in computational cost per step:

- **Sparse MoE Layers**: Replace the standard Feed-Forward Network (FFN) in the Transformer layers with a Sparse MoE layer.
- **Gating**: Top-1 or Top-2 gating to select active experts.
- **Experts**: 8 to 16 small experts.
- **Benefit**: Allows the model to specialize different experts for different types of reasoning steps or problem components.

## 3. Learning Paradigm: Contrastive Learning

The user requested learning from both positive and negative examples.

- **Objective**: Standard TRM uses Cross-Entropy loss on the final prediction. TRMC adds a contrastive loss.
- **Positive Examples**: The correct solution/label.
- **Negative Examples**:
    - Incorrect solutions from the dataset.
    - "Hard negatives" generated by slightly perturbing the correct solution.
    - Previous incorrect predictions from the model's own recursive steps.
- **Loss Function**: InfoNCE or Triplet Loss applied to the latent state $z_t$.
    - $L_{contrastive} = -\log \frac{\exp(\text{sim}(z_t, \text{feat}(y_{pos})) / \tau)}{\sum_{j} \exp(\text{sim}(z_t, \text{feat}(y_j)) / \tau)}$
- **Benefit**: Forces the model to explicitly distinguish *why* a solution is wrong, leading to better reasoning boundaries.

## 4. Hardware Optimization (RTX 3070)

- **VRAM Target**: < 8GB.
- **Techniques**:
    - Mixed precision (BF16/FP16).
    - Gradient checkpointing (if deep recursion is used).
    - Efficient MoE kernels (e.g., using `megablocks` or custom kernels if available, but staying with pure PyTorch for broad compatibility).
